# 2팀 실시간 배팅 게임 웹앱 최종 통합 개발 기획서

아래 요구사항 전체를 하나의 실제 작동 가능한 웹앱으로 구현해주세요.

화면 시안만 만드는 것이 아니라, 진행자 노트북과 각 팀 휴대폰에서 동시에 접속하여 실제 게임을 운영할 수 있어야 합니다.

기능 간 조건이 충돌할 경우 이 문서에서 뒤에 작성된 조건을 우선 적용해주세요.

앱 전체에서 ‘성공·실패’라는 용어는 사용하지 않고, 모든 결과 용어를 ‘승리·패배’로 통일해주세요.

---

# 1. 프로젝트 개요

교회 수련회 및 레크리에이션에서 사용할 2팀 실시간 배팅 게임 웹앱입니다.

사용자는 다음과 같습니다.

* 진행자 1명: 노트북 또는 PC로 접속
* 1팀 대표 1명: 휴대폰으로 접속
* 2팀 대표 1명: 휴대폰으로 접속

각 팀에서는 대표 1명만 한 대의 휴대폰으로 접속합니다.

진행자가 게임 전체를 운영하고, 각 팀은 자기 팀의 배팅만 입력합니다.

진행자 화면과 팀 화면은 실시간으로 동기화되어야 합니다.

Firebase, Supabase 또는 유사한 실시간 데이터베이스를 사용해주세요.

---

# 2. 사용자 역할 및 권한

앱에는 다음 3가지 권한이 필요합니다.

* 진행자
* 1팀
* 2팀

## 진행자 권한

진행자만 다음 기능을 사용할 수 있습니다.

* 게임방 생성
* 게임 설정 변경
* 팀 이름 변경
* 시작 점수 변경
* 라운드 시작
* 다음 라운드 진행
* 현재 라운드 변경
* 양 팀 점수 확인
* 양 팀 배팅 완료 여부 확인
* 양 팀 실제 배팅 금액 확인
* 팀 배팅 취소 및 수정
* 승리·패배 판정
* 결과 적용
* 결과 되돌리기
* 팀 점수 직접 수정
* 이벤트 선택
* 이벤트 설정
* 이벤트 실행
* 랜덤 이벤트 추첨
* 이벤트 취소
* 이벤트 기록 확인
* 게임 종료
* 전체 게임 초기화

## 팀 권한

팀 사용자는 다음 기능만 사용할 수 있습니다.

* 자기 팀 현재 보유 포인트 확인
* 자기 팀 일반 배팅 입력
* 자기 팀 배팅 확정
* 진행자가 요청한 추가 배팅 입력
* 자기 팀 승리·패배 결과 확인
* 이벤트 발생 안내 확인
* 자기 팀에 적용된 이벤트 결과 확인
* 최근 이벤트 내용 확인

팀 사용자는 진행자 전용 기능에 접근할 수 없어야 합니다.

단순히 버튼을 숨기는 방식이 아니라 서버 권한에서도 차단해주세요.

팀 사용자가 주소를 직접 입력하거나 개발자 도구를 사용하더라도 다음 기능을 실행할 수 없어야 합니다.

* 이벤트 실행
* 점수 강제 변경
* 승리·패배 결과 적용
* 라운드 변경
* 전체 초기화
* 다른 팀 배팅 확인

---

# 3. 접속 방식

진행자가 게임방을 생성하면 게임방 코드를 생성해주세요.

예시:

* 게임방 코드: INTO26
* 진행자 비밀번호
* 1팀 접속 코드
* 2팀 접속 코드

각 팀 대표는 게임방 코드와 자기 팀 접속 코드를 입력하여 접속합니다.

한 팀은 한 기기만 접속하는 것을 기본으로 합니다.

진행자는 기존 팀 접속을 강제로 해제하고 새로운 기기에서 다시 접속하도록 할 수 있어야 합니다.

---

# 4. 기본 게임 설정

진행자는 게임 시작 전에 다음 항목을 설정할 수 있어야 합니다.

* 1팀 이름
* 2팀 이름
* 시작 포인트
* 마이너스 점수 팀의 최대 일반 배팅 한도
* 효과음 사용 여부
* 모바일 진동 사용 여부
* 관전자 화면 사용 여부
* 이벤트 공개 기본값

기본값은 다음과 같습니다.

* 팀당 시작 포인트: 500P
* 현재 라운드: ROUND 1
* 마이너스 점수 팀 최대 일반 배팅 한도: 500P

팀 이름과 설정값은 게임 도중에도 진행자가 변경할 수 있어야 합니다.

---

# 5. 점수 기본 규칙

두 팀은 각각 500P로 시작합니다.

점수에는 최저 한도가 없습니다.

점수는 0P 아래로 내려갈 수 있으며, 마이너스 점수도 허용합니다.

예시:

* 500P
* 0P
* -100P
* -1,250P
* -1,000,000P

마이너스 점수가 된 팀도 탈락하지 않고 계속 게임에 참여합니다.

다음 모든 점수 계산에서 마이너스를 허용합니다.

* 승리 결과
* 패배 결과
* 점수 지급
* 점수 차감
* 점수 이전
* 점수 교환
* 강제 추가 배팅
* 배팅 배수
* 진행자의 직접 점수 수정
* 이벤트 적용

점수가 마이너스가 되더라도 0P로 보정하지 말고 실제 계산값을 그대로 적용해주세요.

---

# 6. 일반 배팅 규칙

진행자가 라운드를 시작하면 각 팀 대표가 자기 휴대폰에서 배팅 포인트를 입력합니다.

배팅 금액은 자유 입력입니다.

1P 단위의 정수라면 자유롭게 입력할 수 있어야 합니다.

예시:

* 1P
* 37P
* 168P
* 499P

다음 값은 입력할 수 없습니다.

* 음수
* 소수
* 숫자가 아닌 값
* 빈 값
* 허용 범위를 초과한 값

## 현재 점수가 양수일 때

현재 보유 포인트가 양수라면 일반 배팅 가능 범위는 다음과 같습니다.

* 최소 배팅: 0P
* 최대 배팅: 현재 보유 포인트

예시:

현재 점수가 350P이면 0P부터 350P까지 배팅할 수 있습니다.

## 현재 점수가 0P 이하일 때

현재 점수가 0P 또는 마이너스인 팀도 계속 배팅할 수 있어야 합니다.

이 경우 진행자가 설정한 ‘마이너스 점수 팀 최대 일반 배팅 한도’를 적용합니다.

기본값은 500P입니다.

예시:

* 현재 점수: -200P
* 최대 일반 배팅 한도: 500P
* 배팅 가능 범위: 0P~500P

---

# 7. 팀 화면 기본 구성

팀 화면에는 다음 항목을 표시해주세요.

* 자기 팀명
* 자기 팀 현재 보유 포인트
* 현재 라운드
* 배팅 입력창
* 배팅 확정 버튼
* 배팅 완료 상태
* 상대 팀 배팅 완료 여부
* 자기 팀 승리·패배 결과
* 이벤트 발생 안내
* 자기 팀 이벤트 적용 결과
* 가장 최근 이벤트 안내
* 필요한 경우 추가 배팅 입력창

진행자 전용 메뉴는 절대 표시하지 않습니다.

---

# 8. 팀 화면의 현재 보유 포인트 상시 표시

팀 화면 상단에는 자기 팀의 현재 보유 포인트를 크고 명확하게 고정 표시해주세요.

다음 모든 상황에서도 계속 보여야 합니다.

* 라운드 시작 전
* 배팅 입력 중
* 배팅 완료 후
* 상대 팀 배팅 대기 중
* 게임 진행 중
* 결과 대기 중
* 이벤트 발생 중
* 이벤트 팝업 표시 중
* 승리·패배 결과 확인 중
* 다음 라운드 대기 중

예시:

1팀

현재 보유 포인트
**-250P**

ROUND 4

배팅할 포인트를 입력해주세요.

보유 포인트는 결과나 이벤트가 적용되면 새로고침 없이 즉시 변경되어야 합니다.

---

# 9. 팀 배팅 화면

배팅 입력창은 모바일에서 숫자 키패드가 바로 열리도록 구현해주세요.

예시:

현재 보유 포인트
**500P**

ROUND 1

배팅할 포인트를 입력해주세요.

[숫자 입력창] P

[50P] [100P] [200P] [최대]

[배팅 확정]

빠른 선택 버튼은 선택 사항이며, 직접 입력이 기본입니다.

---

# 10. 배팅 확정

팀이 배팅 확정 버튼을 누르면 확인 팝업을 표시해주세요.

예시:

정말 150P를 배팅하시겠습니까?

확정 후에는 직접 수정할 수 없습니다.

[다시 입력] [배팅 확정]

배팅 확정 후에는 팀이 직접 수정할 수 없습니다.

수정은 진행자만 할 수 있습니다.

확정 후 팀 화면에는 실제 배팅 금액을 계속 보여주지 말고 다음과 같이 표시해주세요.

✅ 배팅 완료

결과가 입력될 때까지 기다려주세요.

자기 팀이 입력한 배팅 금액도 대기 화면에서는 숨겨주세요.

---

# 11. 상대 팀 배팅 비공개

팀은 상대 팀의 다음 정보를 절대 볼 수 없어야 합니다.

* 일반 배팅 금액
* 입력 중인 금액
* 추가 배팅 금액
* 최종 배팅 금액
* 비공개 이벤트 내용
* 진행자 이벤트 설정값
* 상대 팀 현재 점수

팀 화면에는 상대 팀의 배팅 완료 여부만 표시할 수 있습니다.

예시:

* 상대 팀 배팅 대기 중
* 상대 팀 배팅 완료

실제 배팅 금액은 표시하지 않습니다.

상대 팀 배팅 정보가 팀용 API 응답이나 클라이언트 데이터에도 포함되지 않도록 해주세요.

---

# 12. 진행자 배팅 관리 화면

진행자 화면에서는 다음 항목을 확인할 수 있어야 합니다.

* 현재 라운드
* 1팀 현재 점수
* 2팀 현재 점수
* 각 팀 배팅 완료 여부
* 각 팀 일반 배팅 금액
* 각 팀 추가 배팅 금액
* 각 팀 최종 배팅 금액

진행자 화면에서도 실제 배팅 금액을 처음에는 숨길 수 있도록 해주세요.

예시:

ROUND 1 배팅 현황

* 1팀: 배팅 완료
* 2팀: 배팅 대기

[배팅 금액 확인]

진행자가 버튼을 눌렀을 때만 실제 금액이 표시되도록 합니다.

진행자가 화면을 빔프로젝터로 공유하고 있을 수 있으므로 실수로 배팅 금액이 공개되지 않도록 해주세요.

---

# 13. 승리·패배 판정

앱 전체에서 ‘성공·실패’라는 표현을 사용하지 않습니다.

모든 결과는 다음 용어를 사용합니다.

* 승리
* 패배
* 대기

데이터베이스 상태값은 다음과 같이 사용할 수 있습니다.

* WIN
* LOSE
* PENDING

게임 종료 후 진행자가 각 팀 결과를 직접 선택합니다.

1팀 결과:

* 승리
* 패배

2팀 결과:

* 승리
* 패배

다음 조합을 모두 허용합니다.

* 양 팀 모두 승리
* 양 팀 모두 패배
* 1팀 승리 / 2팀 패배
* 1팀 패배 / 2팀 승리

결과 적용 전 확인 팝업을 표시해주세요.

예시:

1팀: 승리 / +150P
2팀: 패배 / -300P

이 결과를 적용하시겠습니까?

[취소] [결과 적용]

---

# 14. 승리·패배 점수 계산

기본 배팅 배수가 1배인 경우 계산 방식은 다음과 같습니다.

## 승리

현재 점수 + 최종 배팅 포인트

## 패배

현재 점수 - 최종 배팅 포인트

예시:

1팀:

* 기존 점수: 500P
* 최종 배팅: 150P
* 결과: 승리
* 변경 후 점수: 650P

2팀:

* 기존 점수: 100P
* 최종 배팅: 300P
* 결과: 패배
* 변경 후 점수: -200P

---

# 15. 팀 승리·패배 결과 화면

진행자가 결과를 적용하면 팀 화면에 자기 팀의 결과를 표시합니다.

## 승리 화면

🏆 승리!

최종 배팅 포인트: 150P
획득 포인트: +150P
현재 보유 포인트: 650P

## 패배 화면

💥 패배

최종 배팅 포인트: 300P
차감 포인트: -300P
현재 보유 포인트: -200P

팀 화면에는 상대 팀 배팅 금액이나 점수 변화 상세 내용을 표시하지 않습니다.

---

# 16. 진행자 전용 이벤트 시스템

이벤트의 선택, 설정, 실행, 수정, 추첨, 적용, 취소 기능은 진행자 화면에서만 사용할 수 있어야 합니다.

팀 화면에는 다음 항목을 절대 표시하지 않습니다.

* 이벤트 메뉴
* 전체 이벤트 목록
* 이벤트 선택 버튼
* 대상 팀 선택
* 점수 및 배수 설정값
* 이벤트 후보 목록
* 랜덤 추첨 전 후보
* 실행 전 예상 결과
* 이벤트 적용 버튼
* 이벤트 취소 버튼
* 진행자 전용 메모

팀은 이벤트를 직접 조작할 수 없습니다.

단, 진행자가 이벤트를 실제로 실행하면 팀 화면에도 이벤트가 발생했다는 사실은 반드시 표시해주세요.

---

# 17. 팀 화면 이벤트 표시 원칙

팀 화면에는 이벤트 발생 시 다음 내용을 표시합니다.

* 이벤트가 발생했다는 사실
* 공개가 허용된 이벤트 이름
* 자기 팀에 적용된 내용
* 자기 팀의 점수 변화
* 자기 팀 변경 전 점수
* 자기 팀 변경 후 점수
* 추가 행동이 필요한지 여부

팀 화면에는 이벤트 발생 직후 전체 화면 팝업을 표시해주세요.

팝업을 닫은 뒤에도 화면에 ‘최근 이벤트’ 영역을 두어 가장 최근 이벤트 1개를 다시 확인할 수 있도록 해주세요.

예시:

최근 이벤트
🔥 배팅 2배 이벤트가 적용되었습니다.

---

# 18. 공개 이벤트 표시

진행자가 이벤트를 공개로 설정하면 팀 화면에 이벤트 이름과 자기 팀 적용 결과를 표시합니다.

예시:

🚨 이벤트 발생!

**양 팀 점수 교환**

두 팀의 보유 포인트가 서로 교환되었습니다.

변경 전 보유 포인트: 700P
현재 보유 포인트: -200P

[확인]

배팅 배수 이벤트 예시:

🔥 이벤트 발생!

**배팅 2배**

이번 라운드의 승리 획득 포인트와 패배 차감 포인트가 2배로 적용됩니다.

현재 보유 포인트: 500P

[확인]

# 19. 특정 팀 이벤트 표시

특정 팀에만 적용된 이벤트는 해당 팀 화면에 이벤트 이름과 자기 팀 결과를 표시합니다.

예시:

🚨 이벤트 발생!

**점수 차감**

이벤트로 인해 100P가 차감되었습니다.

변경 전 보유 포인트: 350P
점수 변화: -100P
현재 보유 포인트: 250P

[확인]

상대 팀 화면에는 기본적으로 이 이벤트를 표시하지 않습니다.

다만 진행자가 ‘발생 사실 공개’를 선택한 경우 상대 팀 화면에는 다음 정도만 표시할 수 있습니다.

🚨 이벤트 발생!

상대 팀에 이벤트가 적용되었습니다.

상대 팀 점수와 상세 내용은 표시하지 않습니다.

# 20. 양 팀 대상 이벤트 표시

양 팀 모두에게 적용되는 이벤트는 두 팀 화면에 이벤트 발생 사실과 이벤트 이름을 표시합니다.

각 팀은 자기 팀의 결과만 확인할 수 있습니다.

예시:

🎲 이벤트 발생!

**양 팀 점수 100P 지급**

점수 변화: +100P
현재 보유 포인트: 600P

[확인]

# 21. 비밀 이벤트 표시

진행자가 이벤트를 비밀로 설정한 경우에도 팀 화면에는 이벤트가 발생했다는 사실을 표시합니다.

정확한 이벤트 이름과 설정값은 숨깁니다.

즉시 점수 변화가 있는 경우:

🔒 비밀 이벤트 발생!

진행자에 의해 비밀 이벤트가 적용되었습니다.

점수 변화: -100P
변경 전 보유 포인트: 350P
현재 보유 포인트: 250P

[확인]

점수 변화가 아직 없는 경우:

🔒 비밀 이벤트 발생!

이번 라운드에 비밀 이벤트가 적용되었습니다.

자세한 내용은 승리·패배 결과에 반영됩니다.

[확인]

# 22. 이벤트 종류

## 이벤트 1: 양 팀 전체 점수 교환

1팀과 2팀의 현재 보유 포인트를 서로 교환합니다.

마이너스 점수도 그대로 교환합니다.

예시:

* 교환 전 1팀: 700P
* 교환 전 2팀: -300P
* 교환 후 1팀: -300P
* 교환 후 2팀: 700P

실행 전 진행자 화면에 변경 전후 점수를 표시하고 확인을 받아주세요.



## 이벤트 2: 배팅 배수

현재 라운드의 승리 획득 포인트와 패배 차감 포인트에 배수를 적용합니다.

진행자가 배수를 직접 입력할 수 있어야 합니다.

예시:

* 1.5배
* 2배
* 3배

100P 배팅에 2배 이벤트가 적용된 경우:

* 승리: +200P
* 패배: -200P

배수 계산 결과의 소수점은 0을 향해 버림 처리합니다.

배팅 배수로 인해 점수가 마이너스가 되는 것을 허용합니다.

===

이벤트 설명

기본:
1팀 500P 배팅 후 WIN => 700P 얻음
2팀 200P 배팅 후 LOSE => 배팅한 금액(200P) 잃음

-----

점수 교환:
1팀 1350P 보유 => -200P 보유
2팀 -200P 보유 => 1350P 보유

-----

배수 배팅(ex. 2배 설정):
1팀 300P 배팅 후 LOSE => 배팅한 금액(300P) 잃음
2팀 700P 배팅 후 WIN => 2000P 얻음

===

# 23. 이벤트 공개 방식

진행자는 이벤트별로 다음 공개 방식을 선택할 수 있어야 합니다.

* 전체 공개
* 적용 대상 팀에만 공개
* 발생 사실만 공개
* 비밀 이벤트

## 전체 공개

양 팀 모두 이벤트 이름을 확인합니다.

## 적용 대상 팀에만 공개

적용된 팀만 이벤트 이름과 결과를 확인합니다.

## 발생 사실만 공개

이벤트가 발생했다는 사실만 표시하고 상세 내용은 숨깁니다.

## 비밀 이벤트

‘비밀 이벤트가 적용되었습니다’라고 표시하고 정확한 이벤트 종류와 설정값은 숨깁니다.

어떤 방식이든 자기 팀의 실제 점수 변화가 발생했다면 자기 팀은 점수 변화와 현재 보유 포인트를 확인할 수 있어야 합니다.

* 최근 이벤트 적용
* 최근 점수 수정

되돌리면 점수와 관련 상태가 변경 전으로 정확히 복구되어야 합니다.

이후 다른 결과나 이벤트가 이미 적용된 경우 경고를 표시해주세요.

예시:

이 작업 이후에 다른 점수 변경 기록이 있습니다.

[취소] [그래도 되돌리기]

가능하면 단순 점수 복구가 아닌 상태 스냅샷 또는 트랜잭션 기록을 이용해주세요.

# 27. 진행자 점수 직접 수정

진행자는 언제든지 각 팀 점수를 직접 수정할 수 있어야 합니다.

다음 두 가지 방식이 필요합니다.

* 현재 점수에 특정 값을 추가 또는 차감
* 최종 점수를 특정 값으로 직접 변경

예시:

* 1팀 +100P
* 2팀 -250P
* 1팀 점수를 -500P로 변경

직접 수정 내역도 기록하고 되돌릴 수 있어야 합니다.

# 28. 실시간 동기화

모든 화면은 실시간으로 동기화되어야 합니다.

예시:

* 진행자가 라운드 시작 → 팀 화면에 배팅 입력창 표시
* 팀이 배팅 확정 → 진행자 화면에 즉시 완료 표시
* 진행자가 승리·패배 결과 적용 → 팀 화면 점수 즉시 변경
* 진행자가 이벤트 실행 → 해당 팀 화면에 즉시 이벤트 팝업 표시
* 진행자가 이벤트 취소 → 팀 화면 점수와 최근 이벤트 상태 즉시 복구
* 진행자가 다음 라운드 시작 → 팀 화면 라운드 즉시 변경

새로고침 없이 반영되어야 합니다.

# 36. 기술적 중요 사항

1. 진행자와 팀 권한을 서버 수준에서 구분해주세요.
2. 상대 팀 배팅 정보가 팀용 API 응답에 포함되지 않도록 해주세요.
3. 점수 변경은 트랜잭션 방식으로 처리해주세요.
4. 결과 및 이벤트는 한 번만 적용되도록 중복 방지 로직을 넣어주세요.
5. 실시간 연결이 끊겼다가 복구되면 최신 상태를 다시 불러와주세요.
6. 새로고침 후에도 현재 게임 상태를 유지해주세요.
7. 모바일과 PC 모두에서 정상 작동하는 반응형 웹앱으로 제작해주세요.
8. 점수는 음수와 큰 정수를 안전하게 저장할 수 있어야 합니다.

# 38. 최종 핵심 요구사항

반드시 다음 조건을 지켜주세요.

1. 총 2팀이 참여합니다.
2. 각 팀 대표 1명이 한 대의 휴대폰으로 접속합니다.
3. 두 팀은 각각 500P로 시작합니다.
4. 배팅 금액은 1P 단위로 자유롭게 입력합니다.
5. 상대 팀 배팅 금액은 절대 볼 수 없어야 합니다.
6. 결과는 진행자가 직접 승리 또는 패배로 입력합니다.
7. 앱 전체에서 성공·실패라는 용어를 사용하지 않습니다.
8. 점수는 마이너스가 될 수 있습니다.
9. 마이너스 점수여도 게임에 계속 참여합니다.
10. 팀 화면에는 자기 팀 현재 보유 포인트가 항상 표시됩니다.
11. 이벤트 선택·설정·실행·취소는 진행자 화면에서만 가능합니다.
12. 팀 화면에도 이벤트가 발생했다는 사실은 반드시 표시합니다.
13. 공개 이벤트는 팀 화면에 이벤트 이름과 자기 팀 결과를 표시합니다.
14. 비밀 이벤트도 이벤트 발생 사실은 표시합니다.
15. 팀 화면에는 최근 이벤트 1개를 다시 확인할 수 있는 영역이 있어야 합니다.
16. 팀은 상대 팀 배팅 금액과 비공개 상세 내용을 볼 수 없습니다.
17. 진행자 화면과 팀 화면은 실시간으로 동기화되어야 합니다.
18. 모든 결과와 이벤트는 기록되고 되돌릴 수 있어야 합니다.
19. 모바일 현장에서 빠르고 쉽게 조작할 수 있어야 합니다.
20. 모든 UI는 한국어로 제작해주세요.
