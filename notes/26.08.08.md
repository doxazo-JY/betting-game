# 데일리 노트 — 2026.08.08

## 오늘 요약 (공유용)

전날(8/7) 만든 홈 화면 배경 장식(땅·나무·잔디·별)을 다른 화면으로 넓히고 다듬는 데 하루를 거의 다 썼다. 시작은 "모바일에서 배경 장식이 PC 기준 크기 그대로라 너무 크다"는 지적 — `.home-ground`는 `scaleY`로, 나무는 CSS 변수를 인라인 `style`에서 `var()`로 읽는 방식으로 모바일 축소를 넣었다. 이어서 이 장식을 홈 화면뿐 아니라 1팀/2팀 접속 화면과 중계 화면에도 적용해달라는 요청을 받아 확장했는데, 그 직후 사용자가 실제 아이폰으로 접속해서 세 가지 진짜 버그를 찾아왔다: 스크롤하면 하늘 배경이 문서를 따라 같이 올라가버리는 문제(`background-attachment: fixed`가 iOS Safari에서 안 먹힘 — `.world-sky`라는 독립된 `position: fixed` 레이어로 교체해서 해결), 라운드 기록표가 좁은 화면에서 가로로 잘리는 문제(`whitespace-nowrap` 제거), 홈 화면 타이틀·버튼이 화면을 거의 다 채워 배경이 안 보이는 문제(모바일에서만 폭 78%로 축소). 이 세 가지는 전부 실기기 테스트가 아니었으면 못 잡았을 종류의 버그였다.

오후엔 흙 텍스처 크기를 놓고 대여섯 번을 왔다갔다했다 — PC/모바일 각각 줄여달라는 요청이 나올 때마다 `transform: scale()`을 겹쳐 적용하다가, 한 번은 세로 축소를 잘못된 기준점(`transform-origin: top`)으로 걸어서 흙 무늬 전체가 위쪽으로 쏠려 아래쪽 절반이 텅 비는 버그를 직접 만들어냈다 — 부모 요소의 `scaleY`만으로 세로 축소는 이미 충분한데 자식 레이어에 세로 축소를 중복으로 걸었던 게 원인이었다. 팀 화면에는 게임 종료 후 "GAME OVER" 대신 WIN!/LOSE!를 크게 보여주는 뱃지도 추가했다.

가장 오래 끈 건 구름이었다. 처음엔 clip-path로 뭉게구름 모양(원 3개를 겹친 실루엣)을 새로 계산해서 만들고 검은 테두리·음영까지 손으로 그려 넣었는데, 음영으로 넣은 작은 사각형이 "구멍 난 것처럼 보인다"는 지적을 받아 밑변에 맞닿는 띠 모양으로 고쳤다. 그런데 사용자가 결국 "이 정도 디테일은 CSS로 못 낼 것 같다"며 실제 픽셀아트 참고 이미지 두 개(`pixel_cloud_reconstructed.html`, `small_pixel_cloud.html` — 각각 `<i>` 태그 격자로 그려진 완성된 픽셀아트)를 연달아 제공했고, 둘 다 CSS로 재현하는 대신 격자 데이터를 파싱해서 PNG로 직접 구워 이미지 자산으로 썼다(나무 때와 같은 결론 — 미묘한 디테일은 손으로 그리는 CSS보다 실제 이미지가 압도적으로 빠르고 정확하다). 첫 번째 참고 이미지는 왼쪽 가장자리에 끊긴 픽셀이 몇 개 떠 있다는 걸 사용자가 직접 스크린샷에 동그라미를 쳐서 짚어줬고, 그 부분만 정리해서 반영했다. 마지막으로 진행자 화면에는 구름/별만 보이고(전역 요소라서) 땅·나무는 없어서 어색하다는 지적을 받아, 장식을 진행자 쪽 화면 세 개(방 목록/개별 방 콘솔/기록·되돌리기)에도 마저 적용해 이제 전 화면이 장식을 공유한다.

## 오늘 한 일

### 1. 홈 화면 장식 모바일 반응형 축소

- `.home-ground`(땅)는 좌우 폭을 유지해야 해서 `transform: scaleY(0.5)`로 세로만 축소(가로를 같이 줄이면 화면 끝까지 안 이어짐)
- 나무(`next/image`)는 `className`만으로 폭 지정이 안 먹혀서(Next가 자체적으로 인라인 스타일을 우선시함), CSS 변수(`--tree-left-w` 등)를 인라인 `style`에서 `var()`로 읽는 방식으로 우회 — 이 패턴을 이후 구름 크기 조정에도 재사용

### 2. 배경 장식을 1팀/2팀/중계 화면으로 확장

- `HomeDecoration.tsx` → `SceneDecoration.tsx`로 이름 변경(더는 홈 전용이 아니라서)
- `/play/[teamNo]`(및 팀 이름 입력 화면 `JoinForm`), `/watch`에 추가. 각 페이지의 기존 콘텐츠를 `relative z-10`으로 감싸야 장식 위로 뜬다(`.home-scene`이 `z-index: 0`인 positioned 요소라, 안 감싸면 static 콘텐츠가 오히려 뒤로 깔림)

### 3. 실제 아이폰 테스트에서 발견된 버그 3건

- **스크롤 시 하늘이 같이 올라가는 버그**: `body`의 `background-attachment: fixed`가 iOS Safari에서 안정적으로 지원 안 됨 — `.world-ground`/`.world-stars`와 같은 방식의 독립된 `position: fixed` 레이어(`.world-sky`)로 교체
- **라운드 기록표 가로 잘림**: `<table>`에 `w-full` + 셀에 `whitespace-nowrap`이 같이 걸려 좁은 화면에서 내용이 넘쳐 가로 스크롤이 필요했는데 그 사실을 알기 어려웠음 — 줄바꿈을 허용해서 세로로 자연스럽게 감싸지게 변경
- **홈 화면 UI가 화면을 거의 다 채워 배경이 안 보임**: 모바일에서만 타이틀·버튼 폭을 78%로 줄이고(둘 다 같이 줄여 비율 유지) 세로 간격도 축소

### 4. 팀 화면 최종 승/패 표시

- `FinalRanking`에 선택적 `myTeamNo` prop 추가 — 팀 화면에서 게임 종료 후 "GAME OVER" 옆에 내 팀 기준 WIN!/LOSE!/무승부 뱃지 표시(중계 화면은 두 팀을 동등하게 보여줘야 해서 prop 안 넘김, 그대로 "GAME OVER"만 표시)
- "win, lose만 더 잘 보이게" 피드백으로, 팀 화면에서는 작은 뱃지 대신 "GAME OVER" 텍스트 자체를 빼고 WIN!/LOSE!를 화면에서 가장 크게 보여주는 배지로 교체(중계 화면은 그대로 유지)

### 5. 흙 텍스처 크기 — PC/모바일 여러 차례 조정, 버그 한 번 직접 발생시킴

- "모바일에서 흙 텍스처 하나가 나무 너비보다 크다"는 지적으로 `.home-ground::after`(box-shadow로 그린 흙 구멍 무늬)에 모바일 전용 축소를 추가로 걸었는데, 세로 축소 기준점을 `transform-origin: top`으로 잘못 잡아서 무늬 전체가 위로 쏠려 흙 영역 아래쪽 절반이 텅 비는 버그를 직접 만들어냄 — 원인은 세로 축소가 부모(`.home-ground`)의 `scaleY(0.5)`만으로 이미 충분한데, 자식 레이어에 세로 축소를 중복으로 걸었던 것. 가로만 추가로 축소(`scaleX`)하도록 수정해서 해결
- PC 기본 격자 크기도 두 차례에 걸쳐 축소(6px → 4px → 3px)
- 흙 구멍 무늬가 세로로 74px 영역 중 위쪽 절반(약 43px)에만 계산돼 있던 걸 발견해 전체 영역을 채우도록 좌표 재계산
- 흙 구멍 무늬의 가로 커버 범위(box-shadow 좌표 목록)를 1400px → 3600px로 확장 — 넓은 화면/오른쪽 나무 근처에서 무늬가 끊겨 보이던 문제 해결

### 6. 하늘 장식(별·구름·반짝임) 재배치

- 별 4개, 반짝임(스파클) 6개, 구름 3개(총 13개)의 세로 위치(top%)가 대부분 화면 상단 6~16% 구간에 몰려 있어 한쪽 구석에 뭉쳐 보이던 문제 — 6~72% 구간에 겹치지 않게 고르게 분산하고 좌우도 번갈아 배치

### 7. 구름 — clip-path 재설계 여러 차례 끝에 결국 이미지로 교체(두 번)

- 기존 구름(뭉툭한 십자 모양)이 참고 이미지(여러 뭉치가 겹친 뭉게구름)에 비해 너무 단순하다는 지적으로, 원 3개를 겹친 실루엣을 24×13칸 격자로 계산한 clip-path로 재설계하고 검은 테두리(`drop-shadow` 4방향 겹침)와 음영을 추가
- 처음 넣은 음영(작은 사각형 2개, 흰 면 한가운데)이 "구멍 난 것처럼 보인다"는 지적 — 구름 밑변에 맞닿는 넓은 띠 하나로 교체(격자 계산상 밑변이 정확히 사각형이라 별도 도형 없이 바로 됨). 위치도 화면 위쪽(top 3~26%)으로 재배치("구름은 위에 있어야 자연스럽다")
- 사용자가 자체 제작한 픽셀아트 참고 파일(`pixel_cloud_reconstructed.html`, `<i class="...">` 32×19칸 격자, 색상 4종)을 제공하며 "이 느낌으로, 근데 완벽히 동일하게는 말고" 요청 — 왼쪽 가장자리에 끊긴 픽셀 몇 개가 떠 있는 걸 스크린샷에 동그라미로 짚어줘서, 그 부분(격자 좌표 몇 개)만 정리하고 나머지는 그대로 파싱해 PNG로 구움(`public/cloud-pixel.png`). CSS `clip-path`/`filter` 조합을 전부 걷어내고 `next/image`로 교체
- 곧이어 다른 참고 파일(`small_pixel_cloud.html`, 48×22칸, 테두리 없이 흰색+옅은 하늘색 두 톤)로 다시 교체해달라는 요청 — 같은 방식으로 파싱해 `public/cloud-pixel-small.png`로 교체, 이전 자산 삭제
- 크기 확대 두 차례(70/56/60px → 100/80/85px), 이어서 "모바일은 지금이 딱 맞고 PC만 2배로" 요청 — 나무 때 썼던 CSS 변수 + `var()` 패턴을 그대로 재사용해서 `min-width: 641px` 미디어 쿼리에서만 2배로 키움(200/160/170px)

### 8. 진행자 화면에도 장식 적용, 중계 화면 모바일 텍스트 축소

- "진행자 화면은 구름·별만 있고(전역 요소라서) 땅·나무·잔디가 없다"는 지적 — `SceneDecoration`을 진행자 쪽 화면 세 개(`/admin`, `/admin/[code]/[token]`, `/admin/[code]/[token]/history`)에도 추가, 이제 전 화면이 장식을 공유
- 중계 화면 모바일에서 팀 이름/"입장 대기 중" 라벨과 포인트 숫자가 너무 커 보인다는 지적 — `max-sm:` 반응형 클래스로 모바일에서만 축소(ROUND 뱃지 등은 그대로 유지). 이후 "PC도 작아진 것 같다"는 재확인 요청이 왔지만, 빌드된 CSS를 직접 확인해 `@media (width < 640px)`로 정확히 모바일에만 적용되고 있음을 검증 — 좁은 브라우저 창으로 확인했을 가능성 있다고 안내

### 9. 배포 확인 워크플로 정착

- 사용자가 실제 기기(주로 아이폰 Safari)로 배포된 사이트를 통해서만 확인 가능하다고 알려줘서, 이후로는 커밋·푸시 후 `curl`로 프로덕션 URL 응답 코드와 새로 추가한 에셋(`cloud-pixel-small.png` 등)이 실제로 서빙되는지 확인하는 걸 배포 마무리 루틴으로 굳힘
