# 데일리 노트 — 2026.08.06

## 오늘 요약 (공유용)

전날 실제 앱에 반영한 디자인이 계기가 되어, 정작 앱의 접속 구조 자체가 실사용 그림과 안 맞는다는 걸 깨닫고 하루 종일 링크/접속 아키텍처를 다시 짠 날. 시작은 사소한 지적 두 개였다 — 진행자 화면에만 보이는 안내 문구 하나 빼달라는 것과 "PC에서 만든 방이 모바일에서는 '최근 게임방'으로 안 보이던데 이거 의도한 거냐"는 질문. 이걸 "localStorage는 브라우저별로 따로 저장되기 때문"이라고 설명하다가, 정작 "최근 게임방" 기능 자체가 왜 있는지 되짚어보니 하루짜리 행사에서 방 하나를 계속 켜놓고 쓰는 이 앱엔 애초에 불필요한 기능이었다는 걸 깨닫고 통째로 삭제했다. 그 직후 사용자가 훨씬 근본적인 재설계를 제안했다: "방 생성 기능을 없애고, 메인 화면에는 1팀 접속/2팀 접속/중계 화면만 두자. 참가자에게 공유 안 되는 링크로 진행자 접속이 가능하게 하고, 방을 새로 만들면 메인 화면의 접속 링크는 자동으로 새 방을 가리키게." 즉 지금까지 "방마다 새 토큰 링크를 만들어 팀에게 재배포"하던 모델을, "고정된 링크 하나가 항상 가장 최근에 만든 방을 가리키는" 모델로 바꾸자는 것 — 참가자 링크에서 토큰을 완전히 없애고 `getCurrentRoom()`(createdAt 최신순 1건)이라는 헬퍼로 "현재 방"을 정의했다. 이 전환 과정에서 진행자 전용 진입점(`/admin`, 참가자에게 링크를 안 알려주는 것 자체가 보호 수단)과 과거 방 기록/삭제/재연결 기능도 같이 만들었다. 이어서 팀 이름을 누가 정하느냐를 두고 몇 번 왔다갔다했는데("팀이 직접 수정?" → "아닌가 진행자가?" → "1명이 폰으로 조작하니 입장할 때 이름 쓰는 것도 좋겠다") 결국 "진행자가 기본값을 안 바꾸면 팀이 처음 입장할 때 딱 한 번만 이름을 입력하는" 절충안으로 정리됐다. 오후엔 Borderless의 "팀 잠금" 기능을 이식할 수 있냐는 질문으로 시작해 상당한 혼선을 거쳤다 — 처음엔 이걸 예전에 폐기했던 "팀 단일기기 강제 접속"과 같은 걸로 착각해서 회의적으로 답했는데, 사용자가 "그건 니가 잘못 이해한 것 같다"고 정정: 단일기기 강제는 다른 기기의 접근 자체를 막는 기능(폐기됨)이고, 지금 원하는 "팀 선택 잠금"은 이미 들어온 화면에서 뒤로가기로 못 나가게 막는, 진행자가 켜고 끄는 기능(별개)이었다. 처음엔 가벼운 확인창을 제안했지만 사용자가 명확히 "하드락을 원한다"고 밝혀서, DB에 컬럼(`participantsLocked`)을 하나 추가하고 브라우저 히스토리를 트랩하는 방식으로 구현했는데, 배포해보니 뒤로가기만 막았지 주소창에 직접 `/`를 쳐서 들어가는 건 못 막는다는 허점이 발견돼 `localStorage`로 "이 기기가 어느 팀인지" 기억해뒀다가 잠긴 동안 홈 화면 자체를 서버에서 막고 자동으로 원래 팀 화면으로 돌려보내도록 한 번 더 보강했다. 마지막엔 자잘한 다듬기 — 탭 제목과 홈 화면 타이틀을 "배�팅 게임"에서 실제 행사 브랜딩인 "인투 오락실"로 바꾸고, 중계 화면에 아직 입장 안 한 팀은 카드를 흐리게 표시하고, 스크롤하면 잔디 배경 아래로 하늘색이 새어 보이던 버그(`body` 배경이 뷰포트가 아니라 문서 전체 높이 기준으로 그려지고 있었음)를 `background-attachment: fixed`로 고쳤다.

## 오늘 한 일

### 1. "최근 게임방" 기능 전면 삭제

- 사용자 질문("PC에서 만든 방이 모바일에서는 왜 안 보이냐")에 localStorage가 브라우저별로 저장된다고 설명하다가, 되짚어보니 이 앱은 하루짜리 행사에서 방 하나를 계속 켜놓고 쓰는 구조라 "여러 방을 나중에 다시 찾아야 한다"는 상황 자체가 안 생긴다는 데 합의
- `RecentGamesList.tsx`, `RegisterRecentGame.tsx`, `src/lib/recentGames.ts` 전량 삭제, 홈/진행자 화면에서 참조 제거

### 2. 참가자 링크 구조 전면 재설계 — 토큰 없는 고정 링크 + "현재 방" 개념

- 사용자가 새 구조 제안: 홈 화면(`/`)엔 1팀 접속/2팀 접속/중계 화면 3개 버튼만, 진행자 접속(방 생성 포함)은 참가자에게 공유되지 않는 별도 진입점으로, 방을 새로 만들면 홈 화면 버튼들은 자동으로 새 방을 가리킴
- `src/lib/currentRoom.ts`의 `getCurrentRoom()` — 별도 상태 테이블 없이 `Room.createdAt` 내림차순 1건으로 "현재 방" 정의(방은 삭제 안 하고 계속 쌓이므로 충분). 참가자 화면 전부(`/play/1`, `/play/2`, `/watch`)가 토큰 없이 이 헬퍼로 방을 찾음 — 보호 수단은 "이 URL을 참가자에게만 공유했다"는 점뿐(`/watch` 무인증 모델과 동일 철학, 오프라인 소규모 행사라 충분하다는 판단)
- `/admin`(신규, 비공개 진입점): 새 게임방 만들기 + 과거 게임방 기록 목록 + 참가자 공유 링크(1팀/2팀/중계) 모음. `/new`는 여기서만 도달 가능하게 변경
- 기존 `/play/[code]/[token]`, `/watch/[code]` 라우트와 토큰 기반 로직(`confirmBet`의 `teamToken` 등) 전량 삭제, `/play/[teamNo]`(teamNo 1|2)로 대체. `LinksPanel`/`CopyableLink`는 `src/components`로 이동(진행자 콘솔과 `/admin` 양쪽에서 재사용)
- 방 삭제(`deleteRoom`, cascade로 배팅/결과/이벤트 기록까지 통째로 삭제)와 과거 방을 다시 "현재"로 되돌리는 기능(`relinkRoom`)도 추가 — 후자는 "현재"가 createdAt 정렬로만 정해지므로 과거 방의 createdAt을 지금 시각으로 갱신하는 방식으로 스키마 변경 없이 구현(부작용: 그 방의 "생성 시각" 표시가 최초 생성이 아니라 마지막 연결 시각으로 바뀜 — 거의 안 쓸 기능이라 감수)
- 진행자 콘솔의 "홈으로"는 `/`(이제 참가자용) 대신 `/admin`으로, 개별 방 콘솔의 "접속 링크" 섹션은 참가자 링크가 고정이라 방마다 보여줄 게 없어져서 제거
- 중계 화면에서 방 코드 표시도 제거("굳이 필요 없을 것 같다"는 피드백)

### 3. 팀 이름 설정 위치 — 몇 차례 방향 전환 끝에 "입장 시 1회 입력"으로 정리

- 처음엔 "팀이 직접 수정하게 할 수 있냐"는 질문 → 바로 "아닌가 진행자가 수정하는 게 나으려나?"로 스스로 재고 → 결국 "1명이 폰으로 조작할 거니까 처음 입장할 때 이름 쓰고 입장하는 것도 좋을 것 같다"로 정리
- 팀 이름을 상시 무인증으로 수정 가능하게 두면 중계 화면에 그대로 노출되는 값이라 방송 사고 위험이 있다고 판단, 완전 자유 수정 대신: 진행자가 방 생성 시 기본값("1팀"/"2팀")을 그대로 두면 그 팀이 `/play/[teamNo]`에 처음 들어올 때 딱 한 번 이름을 입력하는 `JoinForm` 화면이 뜨고, 이후엔 다시 안 물어봄(`setTeamName`, 이름이 기본값이 아니게 된 시점부터 "이미 설정됨" 에러 — 스키마 변경 없이 기본값 여부로만 판단)

### 4. "팀 선택 잠금" 기능 — Borderless 기능 오해 정정 후 하드락으로 구현

- 사용자가 Borderless의 "뒤로가기로 팀 선택 화면에 못 돌아가게 막는" 기능을 이식하고 싶다고 요청. 처음엔 이걸 예전에 "한 장소에 모여 진행하니 필요 없다"고 폐기했던 "팀 단일기기 강제 접속"과 같은 카테고리로 취급해서 회의적으로 답변
- 사용자가 정정: "단일 기기 접속에 대한 건 너가 잘못 이해하고 적어뒀던 것 같은데" — 실제로 둘은 다른 개념이었음. 단일기기 강제는 *다른 기기*의 접근 자체를 막는 것(2026-08-04에 폐기), 팀 선택 잠금은 *이미 들어온 화면*에서 뒤로가기로 못 나가게 막는 것으로, 진행자가 언제든 켜고 끌 수 있는 일시적 기능. `notes/26.08.04.md`를 다시 찾아 확인하고 정정
- AskUserQuestion으로 "가벼운 확인창 vs 하드락 vs 스킵"을 물었는데 사용자가 명확히 "하드락을 원한다"고 답변 — 뒤로가기가 눌려서 팀 선택 화면으로 돌아가면 꼬일 상황이 걱정된다는 이유
- `Room.participantsLocked`(Boolean, 기본 false) 컬럼 추가 — 공유 DB라 스키마 변경 전 확인받고 `prisma db push`(추가적 변경이라 데이터 손실 경고 없이 바로 적용됨)
- 진행자 콘솔에 잠금/해제 토글(`ParticipantLockToggle`) 추가. 켜져 있는 동안 `/play/[teamNo]`(그리고 `JoinForm`)에서 뒤로가기를 누르면 `history.pushState`로 popstate를 계속 무효화해서 그 화면에 붙잡아두는 `BackLock` 컴포넌트 구현 — 세션/로그인 없이 "이 방이 잠겨있나"만 보면 되는 순수 클라이언트 트릭

### 5. 잠금 보강 — 뒤로가기 트랩만으론 주소창 직접 접근을 못 막는 문제

- 배포 후 확인해보니 잠금 중에도 주소창에 `/`를 직접 입력하면 팀 선택 화면에 그냥 들어가지는 문제 발견 — "저거는 아예 저 페이지 자체 접근을 못 하는 걸 원했다"는 피드백
- 해결: `/` 홈 화면을 서버 컴포넌트로 바꿔 매 요청마다 잠금 여부를 확인(`export const dynamic = "force-dynamic"` 추가)하고, `HomeGate` 클라이언트 컴포넌트로 감쌈 — 이 기기가 이미 어느 팀인지 `localStorage`(`myTeamNo`, `/play/[teamNo]` 진입 시 `RememberTeam`이 기록)로 기억해뒀다가, 잠긴 상태에서 `/`에 들어오면 기억된 팀 화면으로 즉시 리다이렉트하고, 처음 보는 기기면 "지금은 참가자 접속이 잠겨 있어요" 안내만 보여주고 버튼 자체를 렌더링하지 않음
- 시크릿창이나 다른 기기로 우회하는 것까지는 안 막아도 된다는 전제는 유지("오프라인에서 다같이 있는 상황이니까")

### 6. 브랜딩 — "인투 오락실"로 일부 텍스트 교체

- 수련회 PPT 타이틀 슬라이드("2026 인투 오락실")를 다시 보여주며 브라우저 탭 제목을 그 이름으로 바꿔달라는 요청 → `layout.tsx`의 `metadata.title` 변경
- 이어서 "다른 곳에 있는 것도 배팅 게임 대신 인투 오락실을 넣어주면 좋을 듯" → 홈 화면 큰 타이틀(기존 "2팀 실시간 배팅 게임")을 PPT와 동일하게 "2026 / 인투 오락실"로, meta description도 브랜드명을 포함하도록 수정

### 7. 자잘한 다듬기

- 중계 화면에서 아직 입장(이름 설정) 안 한 팀은 카드를 `opacity-35`로 흐리게 표시하고 "N팀 · 입장 대기 중"이라고 표기 — "접속하는 순간부터 활성화된 느낌을 주면 좋겠다"는 요청, 팀이 실제로 입장하면 다음 폴링 때 원래 색으로 전환됨
- 스크롤하면 잔디 배경(`.world-ground`, 뷰포트 하단에 고정) 아래로 하늘색이 어긋나 보이는 버그 발견 — 원인은 `body`의 하늘 그라디언트가 `background-attachment: fixed`가 아니어서 뷰포트가 아니라 문서 전체 스크롤 높이 기준으로 그려지고 있었기 때문. 추가해서 해결
