- Borderless(`C:\Users\PC\Desktop\coding\Borderless`) 코드를 직접 조사 — Prisma + `@prisma/adapter-pg`로 Postgres에 직접 연결, 모든 DB 작업을 Next.js 서버 코드(Server Actions)에서만 처리, 권한은 쿠키/비밀 URL 슬러그로 판단, 실시간성은 진짜 push가 아니라 폴링(setInterval)으로 구현하는 훨씬 단순한 패턴이었음

- Prisma 스키마 재설계(`prisma/schema.prisma`), `betting` 전용 Postgres 스키마 유지, `prisma.config.ts`로 마이그레이션은 DIRECT_URL, 런타임은 DATABASE_URL(풀링)을 쓰도록 구성 — Borderless의 `src/lib/prisma.ts` 패턴(globalThis 캐싱)도 그대로 가져옴

### 6. 접속 방식 단순화 (2차)

- 팀 접속도 "게임방 코드 + 팀 접속 코드 입력" 폼(`/join`)이 있었는데, 사용자가 "이 코드 자체가 필요한가, admin처럼 링크로 바로 들어가면 되지 않나"라고 재차 단순화 요청
- `Team.accessCode`(4자리 입력용 코드) → `Team.accessToken`(UUID, URL 전용)으로 전환, `/play/[code]/[token]` 라우트로 직접 접속하도록 변경, `/join` 페이지와 관련 세션 로직 전량 삭제
- 팀 단일기기 강제 접속도 처음엔 세션 토큰(`Team.activeSessionToken`) 방식으로 구현했다가, "어차피 한 장소에 모여있는 상태에서 진행할거라서 굳이 필요 없다"는 피드백으로 관련 필드/로직 전부 제거 — 결과적으로 팀 접속은 토큰 링크 클릭 한 번으로 끝나는 완전히 무상태(stateless) 방식이 됨

### 7. 핵심 게임 루프 구현 (커밋 `775d5ff`)

- `/new`(방 생성) → `/admin/[code]/[token]`(진행자 대시보드) → 팀 링크 공유 → `/play/[code]/[token]`(팀 화면)
- 배팅 라운드: 라운드 시작 → 팀 배팅 입력/확정(상대 팀에는 완료 여부만 노출, 금액 비공개) → 진행자 결과 판정(승리 팀 하나만 선택하면 나머지는 자동 패배) → 팀 화면에 승리/패배 결과 표시 → 다음 라운드
- 진행자 화면 관련 사용자 피드백 3가지를 즉시 반영: (1) 팀/진행자 접속 링크를 상시 노출하지 않고 "링크 보기" 토글 뒤로 숨김(빔프로젝터 노출 우려), (2) "배팅 금액 확인" 버튼을 없애고 배팅 확정 즉시 진행자 화면에 바로 표시(이 화면은 진행자 개인 기기용이라 확인 버튼이 불필요한 마찰이라고 판단), (3) 승패 판정 UI를 "1팀 결과/2팀 결과 각각 선택"에서 "어느 팀이 승리했는지 하나만 선택 → 나머지 자동 패배"로 단순화(기획서는 양 팀 모두 승리/패배 조합까지 허용했지만 실제로는 항상 제로섬이라는 사용자 확인)
